# Knowledge Vault — The Super Admin Guide Book

**For the Knowledge Base team only.**

This book covers the administration console that sits behind Knowledge Vault: the portal
where plan requests are decided, access codes are issued, Knowledge Coins are granted, plans
are set, organizations are inspected and messaged, and administrator accounts are managed.

> **Why this is a separate book.** The end-user manual — *The Main Guide Book* — is published
> with the product and downloadable from the Help page by anybody. Nothing in *this* book
> appears there. Details of the staff console, its sign-in door, its capabilities and its
> bootstrap behaviour are of no use to a customer and of considerable use to someone probing
> the platform, so the two audiences get two books.
>
> **Do not publish this book, link to it from the product, or attach it to a customer
> conversation.** Keep it with the team.

---

## Who this is for

Anyone with a Knowledge Base administrator account: the people who answer plan requests, run
the pricing table, and look after organizations on the platform. It assumes you already know
the product from a customer's side; if you don't, read the Main Guide Book first — you will
be answering questions about it.

## The three rules

1. **Every action is audited.** Approvals, denials, coin movements, plan changes, property
   edits, purges and broadcasts all write a permanent record naming the administrator. Work as
   though someone will read it, because they can.
2. **A purge is final.** Deleting an organization from this console bypasses the customer's
   30-day Recycle Bin. The only way back is the customer's own `.main` file — which you do not
   have and cannot make.
3. **You cannot read a Supreme password, and neither can the platform.** If a customer has
   lost theirs, there is no back door here to offer them. Say so plainly.
